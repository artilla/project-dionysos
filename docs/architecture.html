01 / SYSTEM

짧게 조회하고, 진행을 저장합니다.

로컬 Node 실행과 Sites의 Workers 진입점에서 같은 HTTP 어댑터·계산·배치 로직을 사용합니다. 로컬은 SQLite, Sites 대상은 D1 저장소입니다.

탭을 닫아도 결과는 남습니다.

탭이 열려 있는 동안 한 배치씩 진행합니다. 닫으면 다음 요청은 멈추고, 재접속 후 저장된 진행 상태에서 이어갑니다. 상시 백그라운드 수집이나 알림을 실행하지 않습니다.

하나의 요청, 제한된 작업

카탈로그 한 지역, 시설 목록 한 유형, 또는 객실 최대 5개의 날짜 상태를 처리합니다. 대기열은 서버가 지정한 시간 이후 다음 배치로 재확인합니다.

범위별 복구

완료·실패·미확인 범위를 따로 저장합니다. 중복 실행은 저장소의 임대로 제한하고, 실패한 범위만 재시도합니다. 취소 후에도 성공한 결과는 보존합니다.

Sites 배포는 별도

Workers 진입점과 D1 저장 계약을 준비합니다. 실제 Sites 등록·비밀값 설정·배포·해당 서버에서의 원천 접속 확인은 배포 단계의 작업입니다.

02 / AVAILABILITY

같은 시설에서, 모든 숙박일이 가능해야 합니다.

원천 상태부터 구분

일반 예약 상태 Y이면서 예약 건수 0, 휴무가 아니고 현재 조회 가능 기간 안인 날짜를 공실로 분류합니다. Y만으로 예약 가능이라 표시하지 않습니다. 추첨·우선예약·대기·휴무·미개시·알 수 없는 상태는 별개입니다.

인원과 동일 시설 연박

입실일부터 퇴실일 전날까지 동일 시설의 날짜 상태와 최대 정원·숙박일수 제한을 검사합니다. 월말에는 다음 달을 조회하고, 데이터가 없으면 확인 필요로 남깁니다. 실제 예약 자격은 공식 사이트에서 최종 확인합니다.

세 가지 중복 제거

전체는 숙소·야영장 합집합입니다. 메인 달력은 휴양림 수, 상세 달력은 시설 수, 카드의 총일수는 입실 가능한 날짜 수입니다. 금·토 조건은 입실 요일에만 적용합니다.

불완전한 조회는 그대로 표시

조회 실패를 매진으로 바꾸지 않습니다. 확인된 범위의 결과와 미확인 수, 마지막 확인 시각을 함께 제공합니다. 지난 조회 결과에는 이전 확인 표시를 유지합니다.

03 / AUTH & STORAGE

로그인 정보는 서버에만.

  • 로컬의 ID·PASSWORD는 기존 .env에서 읽습니다. Sites에서는 서버 비밀 환경변수로 주입합니다.
  • 비밀번호를 브라우저·URL·로그·localStorage·DB에 저장하지 않습니다. 브라우저에는 찜과 화면 조건만 남깁니다.
  • 원천 쿠키·CSRF·진행 중 대기열 상태는 서버 저장소에서 암호화합니다. 로컬 암호화 키는 .local에, 배포 키는 SESSION_SECRET 환경변수에 둡니다.
  • 정적 파일은 web 빌드 결과만 제공합니다. .env·.local·서버 소스는 정적 경로에 포함하지 않습니다.
  • 상태 변경 요청은 같은 출처와 CSRF 검사를 적용합니다. 개인용 Sites는 비공개 접근 설정과 OWNER_USER_ID 검증을 전제로 합니다. 해당 소유자 신원과 일치하지 않으면 서버는 접근을 거부합니다.
